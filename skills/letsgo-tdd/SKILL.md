# LetsGo 测试驱动开发

LetsGo 要求行为变更采用测试优先的工作方式。

## 固定流程

对 `tasks.md` 中的每个行为任务严格执行，不能合并、跳过或重排：

1. **RED**：先添加或修改能证明目标行为的最小测试；运行聚焦测试，确认测试因
   预期缺失行为失败，而不是语法、环境或测试自身错误。
2. **GREEN**：只编写让当前失败测试通过的最小实现；运行同一聚焦测试并确认
   通过。
3. **REFACTOR**：在测试保护下整理实现；没有必要重构时明确记录“无”。再次运行
   聚焦测试并确认仍然通过，风险允许时再运行更广测试。
4. 把每一步的真实命令、结果和必要摘要追加到
   `openspec/changes/<change-id>/tdd-evidence.md`，再勾选对应任务。

## 证据格式

文件第一项必须选择 `模式：TDD`。每个行为任务使用独立的
`## Cycle N：<行为或任务>`，并包含 `### RED`、`### GREEN`、
`### REFACTOR`。RED 的结果必须为失败，GREEN 和 REFACTOR 的结果必须为通过。

不得把先写实现后补测描述成 RED，也不得编造命令或结果。命令未实际运行就不能
记录为证据。

## 豁免

只有纯文档、注释、模板、仅测试或其他不改变生产行为的修改可以使用
`模式：豁免`。必须在 `## 豁免` 中写明具体理由、实际验证命令和通过结果。涉及生产行为、缺陷修复、
接口或数据流变化时不得豁免。
