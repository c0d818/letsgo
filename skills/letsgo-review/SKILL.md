# LetsGo Review

## 职责

通过可重复修订的审查循环判断当前实现是否符合已批准规格并达到可发布的工程质量。

## 输入

- 当前变更的 proposal、design、specs 和 tasks
- 代码差异、测试和验证证据
- 当前阶段的验收标准与风险约束

## 执行流程

1. 审查规格符合性：确认每项需求均已实现、明确延后或仍然开放。
2. 审查工程质量：查找缺陷、缺失测试、行为回归、边界不清和多余抽象。
3. 按严重程度排列问题，并尽量附带具体文件位置和可执行的修复建议。
4. 存在阻塞问题时判定不通过；证据充分且没有阻塞问题时说明通过理由。

## 输出

输出按严重程度排序的问题清单、修复方向和最终审查结论。

## 边界

- 审查必须基于实际文件和证据，不根据对话记忆猜测。
- 不夸大或编造证据。
- 审查本身不修改文件或推进状态。
